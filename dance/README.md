# 10a-1 · EDM v3 데스크톱 군무

[실행 Issue #29](https://github.com/hjunnnS/meta-club/issues/29) · [시험 기준 맵 aeae8fe](https://github.com/hjunnnS/meta-club/commit/aeae8fe969739485fb71eb2aa7e248821db9c3f5)

중앙 원형 플로어에 시험 아바타 60개와 AI 손님 5개를 배치했다. 두 엔진이 같은 맵과 같은 군중 GLB를 읽는다. 시험 모델 한 개는 삼각형 604개와 관절 11개로 구성된다. AI는 금색 표식으로 구분한다. 배경형 3개는 박자에 맞춰 춤을 추고 반응형 2개는 정해진 신호에 팔을 들어 올린다. 모든 동작은 로컬 시간으로 재현한다.

## 측정 조건

- MacBook Pro, Apple M5 Pro, macOS 26.6.2, 데스크톱 Chrome 156, WebGL 및 ANGLE Metal 하드웨어 가속. 렌더 해상도 1920×1080, 픽셀 비율 1, MSAA와 그림자 끔.
- Babylon.js 9.35.0과 PlayCanvas 2.23.3에 같은 카메라 궤적, 60° 수직 시야각, 방향광 2개, 120 BPM 군무를 적용했다. 두 엔진의 재질 표현으로 화면 밝기에는 약간 차이가 있다.
- 중앙 플로어 눈높이 2.6m와 2층 데크 눈높이 5.65m에서 각각 측정했다. 시점마다 4초 예열 후 12초씩 3회 기록했고, 두 번째 회차에는 엔진 순서를 바꿨다.
- 각 회차에서 0초, 1.5초, 4.5초의 자세에 고유 색상을 입혀, 깊이 가림 후 몸체가 4픽셀 이상 보이는 인원을 셌다. 이 판독과 캡처는 프레임 측정 시간에서 제외했다.
- 프레임 간격은 브라우저 애니메이션 콜백 간격이다. p95는 프레임 간격의 95백분위이며 작을수록 매끄럽다. 이 시험의 범위는 한 기기의 로컬 렌더링이다. 실제 접속자 60명, 서버 동기화, 장시간 안정성, 다른 기기의 성능은 별도 검증 대상이다.

## 측정 결과

FPS와 p95 대표값은 3회 측정의 중앙값이다. 괄호 안은 회차별 p95 최솟값과 최댓값이다.

| 엔진 | 시점 | 평균 FPS 대표값 | p95 프레임 간격 (회차 범위) | 보인 시험 아바타 + AI |
|---|---|---:|---:|---|
| Babylon.js | 중앙 | 120.0 | 9.1ms (9.1–9.1) | 60 + 5 |
| Babylon.js | 2층 데크 | 120.0 | 9.1ms (9.1–9.2) | 60 + 5 |
| PlayCanvas | 중앙 | 120.0 | 9.2ms (9.1–9.2) | 60 + 5 |
| PlayCanvas | 2층 데크 | 120.0 | 8.9ms (8.9–9.2) | 60 + 5 |

두 엔진 모두 이 장면에서 60 FPS에 해당하는 프레임 예산(약 16.7ms) 안에 p95가 들어왔다. 36번의 가시 인원 판독에서 모두 65개가 확인됐다. 평균 FPS가 약 120에 모여 이 결과만으로 엔진 간 성능 여유의 우열을 판정하기 어렵다.

마지막 회차의 PlayCanvas 데크 측정 중 브라우저가 장면을 다시 불러와 해당 표본이 중단됐다. 완료한 11개 표본을 보존하고 같은 기기와 설정의 새 Chrome 세션에서 마지막 표본을 다시 측정했다.

## 다시 열기

이 디렉터리에서 `npm ci --ignore-scripts` 후 `npm run preview`를 실행하고 터미널에 표시된 주소를 연다. 엔진 선택 상자와 중앙 플로어·2층 데크 버튼으로 시점을 비교한다. 같은 컴퓨터에 Chrome이 설치되어 있으면 `npm run bench`로 네 장면을 재측정할 수 있다. 측정 중에는 Chrome을 전면에 둔다.

`python3 build_crowd.py`로 시험 군중을 다시 생성한다. `python3 offline.py edm-dance.html`로 엔진과 모델이 내장된 단일 미리보기 파일을 만들 수 있다.
