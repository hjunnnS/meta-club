# EDM 공동 체험: 독립 브라우저 3개 한정 확인

- 관리: Milestone G4 / Epic #3 / Implementation #174 / PR #175.
- 대상 소스: ac2cd00 (URL 자동 입장 및 공동 오프닝 복구 반영본).
- 진입: 기존 공개 Sites `/clubs/edm/` → 실행 중인 Mac Colyseus 서버.
- 환경: 같은 Mac의 IAB, Chrome 시크릿 창, Safari 개인정보 보호 창. 서로 다른 쿠키 저장소를 사용하는 실제 브라우저 3개이며 실제 참가자/기기 3대의 시험과는 구분한다.
- 범위: 사용자가 요청한 1회 동시 접속·캐릭터·행동 공유·음악·기존 연출 확인만 수행. 코드/연출 변경, 모바일/부하/장시간 반복 시험 없음.

## 확인 결과

1. 세 브라우저 모두 번호/코드 입력 없이 입장했고, 각 화면에 실제 접속 3명이 표시됐다.
2. 서로 다른 방문객 세 명을 화면에서 확인했다. 각각 이동 후 IAB 사이드 스텝, Chrome 디스코 포인트, Safari 팔 올려 점프를 선택했고, 다른 화면에서도 세 캐릭터의 서로 다른 춤이 보였다.
3. 브라우저의 자동 오디오 차단 시 음악 시작을 한 번 누른 뒤, 세 화면 모두 Neon Horizon · Treblo와 음악 재생 중 상태를 확인했다. Chrome과 Safari에는 실제 오디오 재생 표시도 나타났다. 정밀한 샘플 단위 오디오 동기화 측정은 수행하지 않았다.
4. 기존 전광판의 DJ/그래픽 전환, 바닥 타일/별 연출, 객석·벽 광선 움직임과 예정된 공연 진행을 확인했다. 같은 채널의 공연 순서/카운트다운이 이어졌고 확인 중 접속 끊김은 보이지 않았다. 기존 모든 효과를 개별 시험 버튼으로 재시험한 것은 아니다.
5. 종료 시 IAB 시험 탭, Chrome 시크릿 시험 탭, Safari 개인정보 보호 시험 탭을 닫았다. Chrome/Safari 시험 창 종료를 확인했다. 사용자용 Mac 서버와 통로는 계속 실행한다.

## 관찰 사항

- 입장 직후 두 방문객의 시작 위치/이름이 겹쳐 보이는 순간이 있었다. 이동 후 세 명이 분리되어 정상적으로 보이고 춤이 공유됐다. 시작 위치 겹침은 별도 보완 후보로 남기며 이번 요청에서는 수정하지 않았다.
- 브라우저가 자동 재생을 제한할 때 소리 켜기 1회가 필요하다. 기존 안내/버튼을 사용했으며 브라우저 보안 정책은 변경하지 않았다.

이번 커밋은 이 확인 기록만 추가한다. 음악·캐릭터 동작·맵·기존 클럽 연출 구현은 변경하지 않았다.
