# EDM v3 데스크톱 통합 시험

[G0 · 10a-2 #32](https://github.com/hjunnnS/meta-club/issues/32) · [선행 10a-1 #29](https://github.com/hjunnnS/meta-club/issues/29). 10a-1의 기존 군무 GLB와 카메라를 사용하고 서버가 전파한 사용자·AI 상태가 각 모델의 자세에 반영되도록 한다. 한 엔진·서버 후보 조합을 고정한 지속 부하 시험이다.

## 재현

저장소 최상위에서 실행한다. Node.js, 데스크톱 Chrome, Docker가 필요하다.

```sh
npm ci --ignore-scripts --prefix dance
npm ci --ignore-scripts --prefix validation
docker compose -f validation/soak/compose.yaml up -d
node validation/soak/run.mjs --smoke
node validation/soak/run.mjs
docker compose -f validation/soak/compose.yaml down
```

회차마다 별도 채널과 브라우저를 사용한다. 전체 시험은 후보 정원마다 예열을 포함해 최소 105분이 걸린다. 60세션 3회 중 한 번이라도 기준에 미달하면 50세션, 이어서 필요할 때 40세션으로 같은 시험을 실행한다. 서버 AI는 항상 5개다. 결과 폴더를 인수로 `node validation/soak/report.mjs 결과폴더`를 실행하면 측정 요약이 생성된다.

매 1분 구간의 프레임 간격 p95 ≤16.8ms, 원격 입력 반영 p95 ≤200ms, 서버 틱 처리 p95 ≤40ms, 음악 편차 최대 ≤250ms, 재동기화 3초 이내를 확인한다. 음악의 재동기화 시험은 재생 위치를 의도적으로 이동한 뒤 서버 시각으로 복구한다. 매분 프레임을 판정하므로 장면 전체와 마지막 5분에도 같은 기준을 충족해야 한다. 서버 점유, AI 수, 접속 종료, 음악 정지와 렌더 컨텍스트 손실도 함께 검사한다. 각 JSON에는 장면별 프레임 간격 히스토그램(0.1ms 단위)과 시간 구간별 결과가 있다.

## 2026-11-07~08 실행

[9회 본 시험 및 회차별 수치](results/2026-11-07T14-32-48.334Z/README.md). 60·50·40세션에서 각각 AI 5명을 유지한 채 30분씩 3회, 총 270분을 측정했다. 세 후보 모두 세 회차에서 프레임, 서버, 정원, 재접속, 음악 위치 오차의 수치 기준을 충족했다. 별도의 보수적인 재생 준비 상태 검사에서는 세 후보 모두 2/3회 통과했다. 60명에서 1개, 50명에서 2개, 40명에서 1개 표본이 일시정지 또는 현재 오디오 프레임 준비 미완료로 집계됐다. 두 상태를 합산한 계측이라 원인, 지속 시간, 가청 끊김 여부는 판별할 수 없다. 인원을 낮춰도 현상이 재현됐다. 재시험은 60세션에서 루프 경계, 위치 보정, waiting/playing/seeked 이벤트와 실제 출력의 연속성을 같은 시각으로 기록하는 것이 우선이다.

[예열 보정 전 중단 기록](results/2026-11-07T14-25-09.767Z/60-1-progress.json)은 예열 중 음악 보정을 누락해 첫 측정 구간에서 1.86초 편차가 발생한 예비 실행이다. 예열 보정을 수정한 뒤 9회 본 시험을 처음부터 동일 설정으로 진행했다. 재생 준비 상태의 이상 표본 0건은 시험 도구에서 추가한 지속성 확인 조건이다. 기존의 3초 이내 음악 위치 편차 250ms 기준과 구분한다.
