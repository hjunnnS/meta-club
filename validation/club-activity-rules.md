## 구현
- 귓속말: 성공 전송부터 사용자별 2초. 빠른 요청은 남은 시간과 함께 거절하며 예약하지 않는다. 차단/해제는 간격과 무관하게 즉시 처리. 공연 중에도 사용.
- 외치기: 사용자별 성공 접수부터 30초. 최대 20자/3초 표시, FIFO 대기 3건. 두 양옆 전광판에 같은 문구·닉네임을 표시하고 중앙 방송은 건드리지 않는다. 종료/취소 시 양옆의 원래 방송 복귀. 기존 필터 재사용.
- 정기 레이저·홀로그램 및 퍼레이드 중 외치기는 대기한다. 다음 정기 공연까지 3초보다 적게 남았으면 새 표시를 시작하지 않는다. 진행 중 표시를 시험 공연이 중단한 경우 남은 표시 시간만 복원하고 뒤의 대기 요청보다 먼저 끝낸다.
- 퍼레이드: 기존 NPC 5명·10초. 같은 사용자 시작부터 120초, 클럽 전체는 실제 종료 후 60초(조기 취소/퇴장 포함). 같은 클럽 채널 사이에서도 실행 임대와 준비 시간을 공유한다. 다음 정기 공연까지 15초 이상 남아야 시작하며 공연 중/표시 중 외치기가 있으면 거절한다. 거절 요청은 예약하지 않는다.
- 정기 공연 일정을 늦추거나 음악·조명·레이저·홀로그램·바닥·기본 춤을 정지시키지 않는다. 진행 중 외치기 3초는 먼저 끝내고 퍼레이드를 요청할 수 있다.
- 제한은 서버 측에서 성공 요청만 기록한다. 신원 기준 사용 시간을 채널 인스턴스 사이에서 공유하므로 세션 변경·재입장으로 초기화되지 않는다. 서버 재시작/분산 저장은 후속 실제 호스팅 범위다.
- 독립 Sites 체험은 브라우저 익명 신원과 사용 시각만 로컬 저장한다. 본문/상대/가격/결제 정보를 저장하지 않는다. 새로고침·두 탭에서도 같은 브라우저 사용 간격을 유지한다. 공개 실제 멀티플레이 서버를 배포한 것은 아니다.
- UI에서 남은 시간·공연 대기·대기 건수와 시작 불가 이유 표시. 고정 위치를 공유하는 하단 패널은 하나씩 열려 서로 버튼을 가리지 않는다.
