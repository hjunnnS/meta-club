# G0 서버·음악 검증 결과

2026-11-07 · 맵 기준 05a-2.v2 / d5aa590 · M5 Pro MacBook Pro, 데스크톱 Chrome 156.0.8078.81. 모바일 검증은 이번 요청에서 제외했다. 05a-1과 05a-2 완료 후 서버 03a-1 → 03a-2와 음악 07a-1을 시험했다.

## 서버에서 확인한 것

Colyseus Core 0.16.26과 Nakama 3.27.1을 각각 CPU 1개·메모리 512MiB로 제한하고 20Hz 채널을 구성했다. Nakama의 인증·DB는 별도 PostgreSQL 16 컨테이너에서 실행했다. SDK는 colyseus.js 0.16.22와 nakama-js 2.8.0이다. Chrome 한 페이지의 독립 소켓 60개로 같은 맵 경로의 위치·춤 입력을 150ms마다 40회씩 보냈다. 관측 접속 1개를 60개에 포함했다. 자동 입력은 좌표·상태 메시지만 전송한다.

| 망 | 서버 | 상대 입력 반영 p95 | 활성 틱 핸들러 p95 | 동일 채널 복귀 p95 | 관측 클라이언트 환산 JSON |
|---|---|---:|---:|---:|---:|
| 정상 | Colyseus | 60.7ms | 5ms | 113ms | 33.4KiB/s |
| 정상 | Nakama | 58.7ms | 2ms | 54ms | 33.6KiB/s |
| 열화 | Colyseus | 210.4ms | 2ms | 1,127ms | 33.7KiB/s |
| 열화 | Nakama | 331.7ms | 3ms | 2,155ms | 33.8KiB/s |

- **정원·일관성** — 네 조합 모두 중복 접속 거절, 마지막 한 자리에 두 요청 중 한 건 허용, 관측된 정원 초과 0건. 관측자 외 59세션의 입력 2,360건 수신, 최종 순번은 60/60 일치했다.
- **복귀** — 조합별 10/10회 기존 채널의 동일 상태·60인 점유를 복원했다. 모두 5초 이내였다. 기존 방이 소멸한 경우 입장이 거절되고 새 방에 사용자 1명·이전 상태 없음이 확인됐다. 이 시험은 연결 종료·재접속을 사용했다. 새 방에서 실제 캐릭터가 안전 지점에 배치되는지는 후속 단계다.
- **선정 판단** — 정상망의 양 후보가 원격 상태 반영 200ms 기준 안에 들었다. 열화망에서는 이 실행의 Colyseus 결과가 빨랐다. 망·후보당 부하 실행 1회라 D-02 최종 선정은 보류한다.
- **계측 방법** — 상태를 보낸 때부터 다른 SDK 접속의 DOM 상태 갱신 프레임 콜백까지 같은 브라우저 시계로 측정했다. 틱 수치는 직전 활성 틱의 애플리케이션 처리 구간(1ms 해상도)이다. 엔진 내부 전체 틱과 실제 디스플레이 스캔아웃은 측정 범위 밖이다. KiB/s는 한 관측자의 디코딩된 상태를 JSON으로 다시 계산한 값으로, 프로토콜 오버헤드 포함 서버 총 송신량은 별도다.
- **열화 조건** — 시험 서버의 클라이언트 응답 포트에만 netem 지연 150ms·패킷 손실 확률 2%를 적용했다. TCP 재전송을 포함한다. 필터 큐에서 Colyseus 142개, Nakama 275개 패킷 드롭을 관측했다. 정상망 200ms 기준은 열화망의 합격선으로 쓰지 않았다.

## 음악 시계

직접 합성한 12초 WAV(220Hz)를 두 방식에 동일하게 사용했다. 새 브라우저 컨텍스트에서 클릭 전 재생 여부를 확인한 뒤 실제 버튼 클릭으로 재생했다. 늦게 합류하거나 재생을 일시 중단한 뒤 다시 동기화하고, 요청 후 약 2.9초 시점의 미디어 재생 위치를 기준 시각과 비교했다. 지연 150ms는 시계 응답의 왕복을 대칭으로 지연한 시험이다. 서버 열화망 시험과 조건이 다르다.

| 시계 방식 | 추가 왕복 지연 | 위치 오차 중앙값 | 최대 오차 | 3초 이내 250ms 기준 |
|---|---:|---:|---:|---:|
| 현재 위치 전달 | 0ms | 54.5ms | 199ms | 6/6 |
| 현재 위치 전달 | 150ms | 141.5ms | 229ms | 6/6 |
| 시작 시각 + 왕복 중간점 시계차 보정 | 0ms | 97ms | 154ms | 6/6 |
| 시작 시각 + 왕복 중간점 시계차 보정 | 150ms | 61.5ms | 173ms | 6/6 |

두 방식 모두 12/12건 충족했다. 추가 지연에서 중앙값과 최대값이 모두 낮은 **시작 시각 + 시계차 보정**을 다음 통합 검증의 우선 후보로 제안한다. 브라우저 로컬 시계에 의도적으로 1.25초 오프셋을 주었고, 참조 시각은 같은 호스트의 별도 시계를 사용했다. 12개 컨텍스트에서 클릭 전 차단은 9회, 허용은 3회였으며 12회 모두 클릭 후 재생됐다. 실제 스피커 간 지연이나 OS 잠금 뒤 복귀는 이 측정에 포함되지 않는다.

## 판정 범위와 다음 검토

이 결과는 단일 데스크톱에서 서버·음악 방식의 동작을 확인한 결과다. Windows 기준 PC의 Chrome·Edge 및 M1 MacBook Air의 Safari 결과는 아직 없다. 현재 Mac의 Safari는 원격 자동화가 꺼져 있었다. 모바일 시험은 제외한다. 검수본 좌표 외에 아바타·AI를 생성하거나 운영 음원을 맵에 배치하지 않았다. 혼합 렌더링 및 운영 정원 판정은 별도 단계다.

## 재현

validation 디렉터리에서 Chrome, Node 22 이상, Docker Compose를 사용한다. 포트 17350과 17351은 로컬 루프백에만 연다. DB는 시험 컨테이너를 내리면 폐기된다.

```sh
npm ci --ignore-scripts
docker compose up -d --wait
node run.cjs colyseus nakama music
bash degraded.sh
docker compose down
```
